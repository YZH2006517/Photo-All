# 编辑器提速：诊断结果与待确认方案

2026-11-11。当前只完成隔离实验，没有修改产品默认算法，没有打包、提交或推送。

## 问题与证据

交互编辑应先及时显示效果，不应要求用户等CPU完成整个原尺寸光谱流程。此前真实RAW界面测试中，原尺寸就绪约9秒，RAW参数完整刷新11.5–13.5秒，光谱原尺寸精算66–119秒。

本轮使用同一张 `raw test/DSC_0772.NEF` 的16bit显影结果作为输入，保持6056×4032、float32 RGB。直接调用模拟器，隔离RAW显影、应用界面和导出编码。

| 实验 | 时间 | 说明 |
| --- | ---: | --- |
| 当前逐像素光谱 | 78.4791秒 | 本进程完成小图初始化后 |
| 上游17³ LUT＋模拟器复用 | 38.4159秒 | 完整原始像素网格 |
| 上游33³ LUT＋模拟器复用 | 38.3228秒 | 完整原始像素网格 |
| 33³ LUT＋CAM16分块计算 | 33.7031秒 | 同一CAM16算法，浮点舍入略有差别 |
| 606×404交互预览，17³ LUT重复 | 0.4014秒 | 不包含首次编译 |
| 606×404交互预览，33³ LUT重复 | 0.4530秒 | 不包含首次编译 |

小图首次初始化12.19秒含首次导入/编译，不用于声称LUT有多少加速。24MP结果不能据此承诺两秒。

对33³ LUT和本轮逐像素参考结果的比较：隔16像素规则抽样95,508点，裁入显示sRGB范围后计算ΔE2000，中位数0.000087、P95为0.000300、最大0.004178；RGB绝对误差另以隔4像素抽样，P99为0.00000276。它仅代表这张夜景、Gold配方、无额外颗粒和光晕的情况，不是全部片种和极端参数的保证。

CAM16分块与同一33³ LUT全数组结果的float32最大差为5.96e-8，并非二进制完全相同。

## 剩余开销

函数级计时确认：LUT加速后38.46秒中，扫描阶段27.41秒，默认CAM16-UCS输出色域压缩占22.88秒；其中色貌模型前后转换、幂函数和大数组矩阵运算开销显著。胶片曝光约4.70秒，显影约4.06秒。恢复上游LUT只能解决部分问题。

预览传输独立实验：PNG压缩级别1编码0.6683秒、解码并计算哈希0.4183秒；BMP编码0.0907秒、解码并计算哈希0.1202秒，解码RGB哈希相同。但BMP文件约73MB，PNG约51MB；未验证浏览器端显示色彩管理和整个HTTP链路。这不是RAW慢十秒或光谱慢两分钟的全部原因，不直接替换协议。

## 三条路线

1. **默认加速，保留精算导出（建议）**：完整像素网格保持不变；交互及默认导出采用经过误差验证的LUT/GPU路径，提供逐像素光谱精算导出。需要接受受控的颜色插值近似。
2. **仅预览加速**：保持当前精算导出语义，编辑先显示快速结果，停止操作后按需细化。导出仍可能慢，不能承诺手机级耗时。
3. **只优化结果一致的路径**：保留现有算法，减少重复显影、解码、管线初始化及内存搬运。收益有限，无法据现有证据承诺两秒。

## 建议实现设计

### RAW输入与交互

保留一次解码/显影的中性源缓存，按RAW设置和文件身份失效。普通调色使用已有GPU中性基底，减少重新请求、解码。RAW曝光等已有近似反馈继续保留；需要原生显影的白平衡、降噪等，先执行实际的小预览显影，再在手势结束后调度原尺寸细化。不要让过时的全图任务挡住下一次调整。

按原图完整像素网格显示或按需原像素查看；较小的即时预览必须明确处于预览阶段，最终导出不能取预览像素。缓存淘汰继续遵守既有显存预算策略，不能无上限保留全图。

### 光谱计算

恢复原生放大机、扫描器LUT服务和持久模拟器。缓存依赖片种、相纸、光源、滤色、预闪等参数，按实际依赖失效，不能无条件复用旧LUT。

进一步对逐像素色彩映射和CAM16输出变换做可缓存的LUT/GPU处理；颗粒、光晕、耦合剂扩散等空间计算单独执行，不能直接全烘进RGB LUT而丢失空间作用。保留全部现有控制项，不通过关闭CAM16、颗粒、光晕或耦合剂来伪造提速。

如默认导出采用近似路径，需要明确可选精算方式，并让预览与所选导出路径一致。旧配方兼容，原图和非破坏编辑数据不变。

### 验证和目标

目标：已就绪普通滑块约100毫秒内反馈；光谱小预览优先达到亚秒；原尺寸加速继续实测，以接近两秒为优化方向，不作为已实现指标。首次编译、冷RAW显影、缓存命中分别统计。

使用现有28张NEF及此前真实JPG，增加不同片种、深阴影、霓虹高饱和色、极端曝光与空间效果的对照。检查尺寸、位深、ICC、取消任务、缓存失效、默认导出与精算差异。现有RAW正方形裁切偏差单独修复和验证，不能把它计作性能优化收益。

## 本地实现与实拍复测

0.10.7 的编辑器采用加速光谱预览，导出可以选逐像素精算。Windows 版 SpektraLab 的 C++/Vulkan 后端和 Photo All 的 Python/NumPy 后端是两套实现。参考本机 SpektraLab 的 `desktop/src/state/session.ts`，本次将冲印预览接到 Spektrafilm 的 `cmy_film` 中间结果，输入或上游参数改变时重新显影。预览先返回交互帧，再细化至原尺寸。

### 原尺寸引擎计时

对已解码的 6056 × 4032 RAW 输入使用 Kodak Gold 200，相同配方关闭颗粒与光晕，逐像素精算 78.479 s，加速计算 11.489 s。原尺寸每隔 16 像素取样，ΔE00 的第 95 百分位为 0.0192。计时范围仅为胶片计算，文件读取、RAW 显影、预览编码及显示另计。

另一次浏览器端完整接管验证中，Portra 400 叠加颗粒、光晕、预闪与自定义色温。后台细化期间再次调节色温，667 ms 出现新的交互帧，再过 37.103 s，浏览器收到原尺寸响应并显示 6056 × 4032 图像。日志在 RAW 数据目录的 `ui-reprint-native-verified/ui-timings.json`。

复测数据保存在 `validation/artifacts/editor-raw-real-2026-11-11-packaged/ui-reprint-final`、`validation/artifacts/editor-full-real-2026-11-11-packaged/ui-reprint-final` 和 `validation/artifacts/spectral-acceleration-2026-11-11/reprint-timings.json`。

## Photo All 自研 Vulkan 接入 · 2026-11-12

原生源代码位于 `product/native/film.cpp` 和 `product/native/film.comp`，通过 `product/film_gpu.py` 接入现有光谱工作进程。SpektraLab 只作为架构参考。实现使用 Khronos Vulkan API，片种与科学参数继续来自现有 Spektrafilm。

已实现 GPU PCHIP 三维颜色插值、逐波长密度积分，以及融合的相纸曝光和显影。融合阶段保留 CPU 小样本黑白参考校准、预闪与滤色计算，再把常数传给 GPU。独立的逐像素 CPU 精算导出继续可选。颗粒、光晕和耦合剂扩散仍采用现有 CPU 实现，当前属于 CPU/GPU 混合管线。

GPU 会话在工作进程内复用，输入输出工作缓冲区按块增长，GPU 计算表缓存上限 96 MiB。底片缓存按显卡本地内存的 1/32 设置，上限 384 MiB，并在图像内容或上游胶片参数变化时失效。大图缓存底片以 float32 存储。显卡优先选择独立显卡，然后比较本地显存容量。设备不可用或执行失败时，已有 CPU 路径接管。

本机 RTX 5080，Gold 200，6056 × 4032，关闭颗粒与光晕的单次实测如下。首次全流程 11.692 s，复用底片调整相纸曝光 4.393 s。相同输入的精算参考抽样 ΔE00 第 95 百分位为 0.00362。开启颗粒、光晕后全流程 33.499 s。该测试计时仅包括胶片引擎，未包含 RAW 解码与浏览器传输。首次全流程用时与此前 CPU LUT 加速的 11.489 s 接近，空间效果尚是主要瓶颈。

浏览器 RAW 验证记录位于 `validation/artifacts/editor-raw-real-2026-11-11-packaged/ui-own-vulkan-fixed`。独立工作进程实际返回的设备都是 NVIDIA GeForce RTX 5080。首次启用 2.889 s，曝光 308 ms，相纸曝光 253 ms，品红滤色 235 ms，预闪 228 ms，耦合剂 296 ms，光晕 337 ms，颗粒 908 ms，累计效果下色温 914 ms。最后再次调整色温 650 ms 出现交互帧，之后 44.800 s 完成原尺寸接管。此完整配方的后台细化仍然很慢。

JPG 验证使用 `E:/醒图over/DSC_1073.JPG`，首次启用 2.395 s，相纸曝光 209 ms，滤色 241 ms，预闪 236 ms。累计开启光晕与颗粒之后，颗粒面积调整 1464 ms，色温 1958 ms。后台再次调整色温后，1066 ms 显示交互帧，随后 46.843 s 完成 4000 × 6000 原尺寸细化。交互和原尺寸工作进程均返回 Vulkan／RTX 5080，浏览器无脚本错误。该数据保存在 `validation/artifacts/editor-full-real-2026-11-11-packaged/ui-own-vulkan`。

构建需要 MinGW C++20、glslangValidator 和 Khronos Vulkan-Headers。执行 `product/native/build.ps1 -VulkanHeaders <include目录>`，生成 `product/engines/photo-all-gpu/photo_all_gpu.dll` 与 `film.spv`。未来打包步骤会同时收录计算库、着色器和 Python 桥接模块。当前版本仍为 0.10.7。
