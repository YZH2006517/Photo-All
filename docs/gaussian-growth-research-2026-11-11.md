# 高斯模型自下而上构建：调研与可落地方案

调研日期：2026-11-11。本轮只调研，不向软件重新加入生成引擎或模型下载入口。

## 对参考画面的判断

截图可以支持“扫描颗粒从基底向枝叶逐渐显现”的视觉描述，但不能证明其采用了高斯泼溅，也不能证明模型来自单张照片。普通彩色点云、3DGS 和预渲染粒子视频均可呈现近似效果。单个静态三维模型的显现动画，与植物真实生长模拟是不同任务。

推荐先实现 **用户导入一个已有高斯模型，播放可逆的自下而上构建动画**。第一阶段不承担从任意单张照片恢复完整物体的承诺，尤其是花叶背面、根系与遮挡区域。

## 引擎比较

| 项目 | 查阅时约星数 | 能力与项目适配 | 结论 |
| --- | --- | --- | --- |
| [Spark](https://github.com/sparkjsdev/spark) | 3.9k | MIT；直接融合 Three.js 网格与高斯。支持 PLY、SPZ、SPLAT、KSPLAT、SOG；GPU 上逐个高斯改变位置、尺寸、透明度和颜色 | **优先**，最契合现有 Three.js 收藏室，但应先验证本项目 Three.js 0.187 与目标 Spark 固定版本的兼容性 |
| [PlayCanvas Engine](https://github.com/playcanvas/engine) | 17.3k | MIT；高斯自定义顶点、片元阶段和完善展示工具，但需要另一套运行时 | 可做独立展示页；不推荐为这个单功能重写现有收藏室 |
| [GaussianSplats3D](https://github.com/mkkellogg/GaussianSplats3D) | 3k | MIT；基于 Three.js，适合浏览已有模型 | 备选；复杂生长效果需扩展渲染逻辑，Spark 的修改器更直接 |

依据：[Spark README](https://github.com/sparkjsdev/spark#features)、[Spark Dyno 文档](https://sparkjs.dev/docs/dyno-overview/)、[PlayCanvas 高斯自定义 Shader](https://developer.playcanvas.com/user-manual/gaussian-splatting/building/custom-shaders/)。星数随时间变化，不代表质量测试结论。

## 动画设计建议（设计方案，不是已经集成）

总时长约 8–12 秒，暗色背景、偏暖底光，成像主体保留原色：

1. **准备**：相机微俯视，少量底部颗粒聚拢。模型解码完成后才开始，避免把下载卡顿混入动画。
2. **基底建立**：扫描面从模型最低点上升，已到达的高斯从小粒子柔和长到原本尺寸。
3. **主体建立**：枝干优先稳定，叶片与花朵略错峰。使用固定随机种子产生局部延迟，避免一条水平切线生硬扫过全部表面。
4. **收束**：残余漂浮颗粒归位，相机缓慢环绕至最终构图。原照片与日期文字在右侧或左侧淡入。

GPU 参数建议：`heightProgress`、`featherWidth`、`scatterAmount`、`settleProgress`、`seed`。逐高斯使用归一化高度与固定噪声确定出现时间，在 Shader 内调节透明度、尺度和少量位置偏移。每帧只上传少量 uniform，不能每帧由 JavaScript 逐点重建百万条数据，也不必重新训练模型。

“枝干先于叶片”的严格语义顺序需要离线分组、手工标注或分割结果。只有普通高斯坐标时，能可靠实现高度扫入和空间错峰，不能自动识别真实植物结构。反向播放、暂停、重播可复用同一时间轴。减少动态效果偏好直接显示成品。

## 来源与生成边界

- 可以先用 Spark 官方 [butterfly.spz 示例](https://sparkjs.dev/assets/splats/butterfly.spz) 验证读取与动效。但示例资产的再分发授权不能由引擎 MIT 许可推定，发布内置模型前需单独核对；本轮没有下载或打包它。
- 用户自带 PLY 文件未必是高斯模型。导入时需检测尺度、旋转、透明度等字段，普通 XYZ/RGB 点云要明确提示为点云，不冒充 3DGS。
- [Apple SHARP](https://github.com/apple-aiml-research/ml-sharp) 是单图近邻视角生成路线，不负责显现动画。其 [模型许可](https://github.com/apple-aiml-research/ml-sharp/blob/main/LICENSE_MODEL) 限定研究用途，并在研究用途定义中排除了产品开发；“免费开源软件”本身不意味着满足该许可条件。因此不建议将其当作本产品可直接分发的默认生成引擎。
- 单张照片缺少背面、遮挡与真实尺度信息。单图生成可以推断内容，但不能保证多数照片都有稳定的绕物完整结构；不能从参考截图推断这种能力。
- 若需要参考图这样的独立花卉且要求绕物观看稳定，优先使用有许可的多视角扫描模型，或自行多角度拍摄后重建。生成与展示应解耦：模型准备好以后，自下而上的动画不依赖其来自哪种重建工具。

## 性能和复杂度

已有模型的加载、对齐、相机与高度显现：中等复杂度。自然聚散、稳定排序、低显存策略、视频导出：中高复杂度。单图生成且覆盖大多数照片：高复杂度、效果不可统一保证。

百万级模型必须同时考虑压缩文件、解码数据、排序缓冲、GPU 纹理和渲染目标；不能把文件大小直接当显存占用。建议独立入口按需加载、退出释放 GPU 资源，限制首版点数并提供质量档位；现有“最高显卡容量”的策略不等于当前 WebGL 上下文一定运行在该显卡上，应参考实际渲染器能力。具体点数与帧率需要将来获得测试授权后，以真实设备测量，不在本轮虚报。

推荐后续顺序：已有模型导入 → 朝向与地面校正 → GPU 高度显现 → 聚散与相机编排 → 保存展示参数 → 单独评估生成模型。现在不恢复已删除的 SHARP 功能。
