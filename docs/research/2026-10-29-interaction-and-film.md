# 交互、性能与胶片模拟

## 0.8 高精度工作台与观片缓存（2026-10-30）

用户选择优先完善现有高精度工作台。实现集中在一个 Editor.tsx 和现有 pixels.py：专业工具栏与参数区、可拖拽裁剪、比例预设、旋转/翻转/拉直、色阶、分段线性 RGB/通道曲线、八段 HSL、细节、局部曝光/饱和度、仿制与周边色调匹配修复。局部操作保存原片归一化坐标，一笔一次历史。现有 RAW、Spektrafilm 和图层工作区沿用原有入口，不将独立实现描述为移植整套 GIMP/Krita/miniPaint，也不声称具备完整蒙版、文字或 PSD 支持。

先修复裁切预览按裁切前尺寸降采样的问题；解码尺寸以最终画幅为目标，RAW 必要时提高显影请求尺寸。原图对比保留几何而旁路调色，未裁切模式复位全部四个裁切字段。服务对单图编辑返回准确的标准化配方快照；前端 committed_recipe 与当前乐观配方分开，旧读取不覆盖已确认的新快照。几何工具需等待保存及实际 img.onload 对应画幅就绪；分别阻塞保存和源图请求的回归确认，旋转后的旧 fallback 画面不能接受错误笔触或裁剪。

观片移除全局照片尺寸滑杆，选中照片可拖角部手柄独立缩放；放大倍率旁明确标注放大镜大小。底部导览右键移除可撤销，首页多图集入口仅移除本次选择范围中的成员，不影响未选择图集。缓存补充解码对象共享与引用计数，目标 192 MiB，当前显示对象可暂超预算；64 MiB Blob 缓存继续保留。完整原图只由解码尺寸与已确认配方确定，511/512 等裁切取整误差不能误标为原生尺寸，较高画质可服务较低显示档位。

最终验证：41 项前端单元测试、89 项 Python 测试（包含实际 NEF/CR2 与原生 16-bit RAW 导出）通过；TypeScript/Vite 与 Rust 0.8.0 release 构建通过。浏览器验证裁切/旋转撤销、曲线、局部笔刷与仿制坐标、一笔一次历史、PNG16 精确像素及源文件不变：`editor-workspace-1793293342182/report.json`；延迟提交/图像就绪保护：`editor-workspace-1793293327743/report.json`。观片六次暖机切换新增源图请求为 0，逐张缩放、放大镜、移除撤销均通过：`lighttable-1793293389964/report.json`；几何、裁切分辨率和连续提交缓存：`cache-geometry-1793293406074/report.json`。

首页多图集移除与五种导出格式：`library-quality-1793293439493/report.json`。真实 release 程序验证编辑待写入时关闭、观片选片待写入时关闭、全屏恢复和后台退出：`native-1793293373067/report.json` 与 `native-1793293383272/report.json`；旧 webview 关闭通道失败兜底：`native-1793293514955/report.json`。最终交互回归 `interaction-1793293502977/report.json` 确认分割线、重开和工具切换均无新增图像请求，延迟撤销读取不覆盖新的已保存参数。所有报告与样本位于 validation/artifacts，产品数据不参与测试。程序仍依赖当前工作区 Python 和引擎资源，不是独立安装包。

## 原图质量与导出实施步骤

本轮集中处理源文件到显示、编辑和导出的完整链路。查看按实际屏幕像素、设备像素比和放大倍率读取源图生成无损 PNG；完整原图尺寸以 size=0 请求，屏幕缓存独立于原片和导出。避免将固定 600px JPEG 再放大。高精度处理采用 float32，16-bit TIFF/PNG 与 RAW 原生显影保留位深；屏幕最后转为 8-bit，JPEG / WebP 的编码能力在导出选项中明确标注。

实施顺序：先补成员移除/撤销与完整源图 API 验证，接入首页图集选择和右键菜单；并行完成 pixels.py 高精度处理与观片台自适应源图显示、镜片边界、图片尺寸和连续倍率。随后接入 PNG16 / TIFF16 / WebP 无损 / JPEG / 原始文件复制导出，以及合成的高精度路径，最后验证真实 RAW、16-bit 渐变与桌面保存关闭。原片始终只读；图集中删除仅移除成员，图库中移除可撤销，不删除磁盘文件。测试与样本继续独立位于 validation/。

0.7 实施结果：主相片处理和六种图层混合均采用 float32 sRGB SDR，完整导出不经过缩略图，也不逐层量化；PNG/TIFF 保留 16-bit，8-bit 仅用于屏幕或明确选择的 WebP/JPEG。测试验证 8192 级渐变合成、16-bit PNG/TIFF 精确像素往返、真实 NEF/CR2、LZW/Deflate、ICC 和透明边缘。支持原始文件字节复制；JPEG 为有损编码，不能把所有输出格式称为无损，也不声称支持 HDR 场景线性管线。依赖已准备在 engines/precision-packages（tifffile、PyPNG、imagecodecs）；不支持的高精度颜色模式明确报错。

首页必选图集，观片范围为所选成员并集，角落仅保留爱心；照片尺寸 60–180%、放大镜 1–20×，倍率和实际屏幕像素共同决定无损源 PNG 请求尺寸，超过显示档位读取完整原图。源图离屏释放解码 URL。单 RGB 折射与 40px guard band 处理镜片蓝边；胶卷外轮廓统一圆角裁切与阴影。编辑工作台同样使用源 PNG，对比分割线只改变显示裁切。

图集右键移除采用成员差量历史，撤销不会删除后来导入其他图集的新成员；图库隐藏只改变可见性。Windows 预览临时文件清理即使失败，也无条件释放共享 flight。两项均先复现、再加入回归测试后修复。

验证产物：`lighttable-1793275056090` 覆盖源 PNG 与 full 请求、离屏释放、尺寸与倍率、镜片、图集选择、爱心和沉浸；`library-quality-1793275696965` 覆盖成员移除、撤销重做及五种格式；`interaction-1793275162760` 覆盖源图编辑、分割线、真实传输并发与缓存；`albums-1793275067913` 验证四层 float 合成和 PNG16 导出。所有产物均在 validation/artifacts 下。

## 0.6 观片交互修订

按实际截图复现并修复两处问题：拖片或 Ctrl+A 触发浏览器原生文字/图片选择，434 字与图片被选中后产生灰色覆盖；观片区禁用原生选择，拖动阻止默认选区，不改变图像参数。原图对比分割线按下时受到通用按钮 active transform 影响，实测竖线偏离裁切边缘约 17.5px；改为无 transform 的绝对定位和独立按下样式，拖动时仍与裁切边界对齐。

首页增加全库观片入口，返回仍为首页；图集入口继续限定当前筛选。并排改为连续胶卷：统一片高，窗口保持比例，片边首尾相接，拖动/滚轮横向滑动，Ctrl+滚轮、按钮和键盘缩放统一约束可见垂直中心及水平边界。选定组图与当前范围的顺序不变。

放大镜默认直径从 640 降到 300 CSSpx，可调尺寸，移除十字、文件名 tooltip 和镜内额外文字；边缘采用渐隐柔光、玻璃反射和软阴影，不使用刻纹硬金属圈。沉浸时画面移动和选片不会持续弹出上下栏；空格或窗口上下边缘临时唤出，悬停工具和键盘聚焦保留可访问性。

新增持久“边框”开关。关闭后平铺、胶卷连排和镜内都只显示照片：片孔、片边、型号、条码、片面反光和标记装饰隐藏，黑侧边清零；平铺高度和连排宽高重算，不占用隐藏装饰的空白。不修改调色、源文件或导出。偏好存在本机 localStorage，浏览器验证覆盖重开保持、两种布局以及配方不变。22 项前端测试和生产构建通过；`lighttable-1793263590612` 为包括边框开关在内的真实浏览器验证，`interaction-1793262815860` 记录分割线按住时对齐、联动分类与撤销缓存回归。

## 胶片电子观片台设计与实现

按用户“胶片电子观片台，需要沉浸模式”的要求，采用共享图库内的独立观片模式：接触表、单张和固定参考帧并排。相比直接嵌入第二套桌面软件，它可以沿用同一图集、筛选范围、配方、预览缓存、RAW/Spektrafilm 显影与持久编辑历史。相比仅给原编辑器加全屏按钮，它保留了胶片条审阅和并排初选。当前范围进入时固定，避免标记后筛选集合变化造成漏看。

调研 [reville/lighttable-digital-darkroom](https://github.com/reville/lighttable-digital-darkroom)，记录版本 `ca55bc489ce80c0fc3b93c55f4efffe738066264`，GPLv3。它是摄影电子暗房项目，与同名 Light Table IDE 无关；调研时约 28 stars，不能称为高星项目。仓库元数据、README 与许可位于 validation/metadata/lighttable-*。本次没有复制或编译其 Rust GPU 引擎，当前观片台由 Photo All 自主实现，不将其表述为整套上游软件已集成。

实现集中为 Lighttable.tsx（观片与保存）和 FilmTable.tsx（实体灯箱与折射镜）：Portal 模态覆盖、底层工作区 inert；胶片台分批摆放 96 帧并按可见范围加载，显示片孔、型号、条码和片边反光，支持自由拖片、一键平铺与桌面缩放平移；关灯时暗透，开启背光后按显示亮度透亮，不改照片配方。单张/双图共用缩放和平移，相邻图预取沿用有界队列。默认沉浸，空闲 1.8 秒淡出 HUD，鼠标/空格唤出，尊重减少动态效果设置；窗口全屏通过 Tauri 原生命令实现，浏览器验证使用 Fullscreen API。退出冻结新输入、排空保存队列、等待未完成的全屏请求后恢复进入前状态。保存失败回滚乐观标记并显示错误；失败任务不永久阻断后续退出。

验证先覆盖选片序列与不同参考帧的规则，浏览器覆盖实际图库、选片落库、撤销重做、缩放、沉浸及全屏。复查发现的失败任务阻断退出与全屏竞态已加入回归脚本，再修复。原生验证补充待写入选片时关闭与后台进程清理。

## 已实现的设计

- 分面统计按其他筛选条件计算当前选项，包括搜索与精选状态，避免数字仍引用全图集。当前选项保留；零匹配选项禁用。
- 原图对比采用同一画幅上的两张独立预览，CSS 裁切与拖动分割线只在本地显示；原图不随配方重读。支持方向键、Home/End、双击归中。
- 首屏按需请求缩略图，前端并发 3，后台解码并发 2；前后端均有有界缓存，磁盘缓存用临时文件原子替换。失败结果短暂共享，避免同一坏图并发重复解码。
- JPEG 小预览使用解码缩放；完整导出不使用低分辨率代理。图集网格使用短位置/透明度过渡，图片更新不反复模糊；侧栏切页和画布过渡响应减少动态效果设置。
- 调色、胶片、选片和批量修改支持持久撤销/重做，快照转移处于 BEGIN IMMEDIATE 事务；空修改不污染历史。读取期间产生的新参数通过本地版本合并保留，过期读取响应不覆盖新状态。图层会话有独立撤销/重做。

## Spektrafilm 接入依据

[官方仓库](https://github.com/andreavolpato/spektrafilm)，固定 revision `3bb2c2d2801ff68b92019cf1dbcbb133d60832bc`，版本 0.3.4。以源码包、官方 `BundleBuilder` 和该版本的 profiles 生成 16 款负片配置。构建器本身负责编码 sRGB 与线性光之间的转换，输入/输出都明确为编码 sRGB；选择 `stops_above_midgray=None` 保留输入的本来曝光，不额外把 SDR 白点推到更高档位。

参考引擎在隔离 Python 3.13.13 环境运行；主服务仍使用原有 Pillow / NumPy。实际交互采用 33³ 色彩 LUT，表轴顺序 `[b,g,r,channel]` 与 Pillow 的 R-fastest 顺序一致，预览和导出共用处理函数。物理计算被预生成，不因为手柄/滑杆拖动启动新的光谱进程。颗粒与光晕不谎称来自上游物理模拟，UI 明确写为 Photo All 附加效果。

核心 GPLv3，数据与生成 LUT 按固定版本的 `SPEKTRAFILM_LICENSE.txt`（CC BY-SA 4.0）保留署名、许可证、revision、参数与修改说明。README 的过时简述不替代该版本具体许可文件。
