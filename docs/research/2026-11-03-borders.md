# Editor export borders · local 0.10.6

The editor has a separate 片边 tool (B). Settings belong to each photo recipe,
share undo and batch synchronization, and are the default export layout. Preview
is a bounded 1200px screen proxy; exports re-render the full source in float32.
The original image rectangle is copied unchanged into the expanded canvas.
Original-file copies and RAW development masters bypass decorative borders.

## Open-source resources actually included

- [romnn/film-borders](https://github.com/romnn/film-borders), MIT,
  `ff428ce31dfc77701941d4cdbd45734dac5976a6`: original `borders/border.png`.
  Only its exterior scan silhouette is applied; center dust never covers pixels.
- [NegativeConverter](https://github.com/lexluthor0304/NegativeConverter), MIT,
  `ff3043976b7cb72266d89e659faa65142c21b635`: original `sprocketFrame.js`.
  The bitmap edge alphabet and numbered block arrangement are adapted locally.
  Stock/generation identification remains unknown; UI labels the barcode a
  frame-number illustration. No manufacturer logo or recovered stock is claimed.
- Both original assets, full MIT copyrights/licenses, source URLs, revisions and
  SHA-256 values are in `product/engines/film-borders`. Stage and build verify
  assets; distribution notices include both full licenses.

These are focused resources, not high-star complete photo engines. Redlamp
(MPL-2.0) was also researched; its code was not copied into this implementation.

## Realistic geometry

The three 35mm layouts use a 24mm image height, 34.98mm film width, KS holes
2.794mm along transport × 1.981mm across it, 4.75mm pitch and 0.51mm corner radius.
The physical axes are independently corrected from the upstream generator.
Portrait images rotate the complete composition so holes run along the sides;
120 medium format has no perforations. These proportions remain fixed rather
than using an arbitrary border-width slider. Panoramas remain uncropped and have
more holes, so this is not a claim of a standard 36×24 exposure gate for all inputs.

Dimension reference: [Kodak Essential Reference Guide, printed p.96–97](https://www.kodak.com/content/products-brochures/Film/kodak-essential-reference-guide-for-filmmakers.pdf#page=98).
The reference document and Kodak artwork are not distributed.

Eleven styles plus none: classic/warm/b&w 35mm, 120, scan edge, slide mount,
instant print, gallery, postcard, cinema and archive card. Date, roll, signature,
frame number, camera/lens/exposure, font and palette are editable. EXIF date falls
back explicitly to file time. Auto roll uses the first sorted active album
membership consistently in preview and export, even for shared photos.

## Focused verification

Six backend checks cover float source preservation, portrait geometry, tiny-photo
text boundaries, settings validation, physical dimensions and actual 16-bit TIFF
export. A real-service browser check covers all 12 choices, EXIF/custom text,
undo/redo, one-photo PNG16 export, unchanged source hash, shared-album/default
layout behavior and dark homepage regression. A separate native executable check
exercises the actual editor preview, PNG16 export and clean close.

The dark-homepage bug was an opaque `.album-card` background combined with old
light-theme badge/plus colors. Cards now remain transparent outside their cover;
badges and controls use the current theme. No full suite or installation test is
required for this local change; generated reports record what actually ran.

Review also fixed a scalar preview-size argument, inconsistent auto roll names,
and unbounded concurrent frame decoding. Frame previews now share two decode
slots, and superseded queued requests are skipped by per-view session tickets.

Version remains 0.10.6. No GitHub upload is authorized for this change.
