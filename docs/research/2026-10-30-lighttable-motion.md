# 观片台收纳、开场与联排播放

用户已直接授权构建；沿用现有观片台，不新增引擎或前端依赖。

- 一键收纳保留照片、摆放位置、缩放和解码缓存，仅把同一图片节点用 transform/opacity 收回下方对应缩略图。点击一键平铺可展开；点击底部照片恢复显示并选择。
- 用户追加要求：收纳后的台面保持空白，不显示中央图标、文字、恢复按钮或台面文字说明；底部导览与工具条仍保留。
- 每次进入观片台仅播放一次开场：从底部导览逐张展开至已保存的台面位置。等首批原图完成加载再展开；超时显示普通台面，不无限等待。普通模式切换不重播。尊重减少动态效果设置。
- 联排增加播放/暂停；按屏幕上每张照片约 6 秒计算速度，48–120 CSS px/s，匀速向左移动，末尾停止。手动拖动、滚轮、缩放、放大镜、选片导航、切换模式和窗口隐藏时暂停。大图库自动续摆下一批。
- 使用 Web Animations API 的合成变换，避免 React 每帧重绘整批照片。暂停从当前显示位置接续，清理 RAF、计时器和 animation；不修改原片与修图配方。

实施顺序：

1. 在现有前端单测中加入滚动时长、边界与收纳坐标测试，先确认失败。
2. 在 model.ts 集中实现纯几何/播放计算，在 FilmTable.tsx 实现节点动画与中断清理；Lighttable.tsx 为导览增加稳定照片标识。
3. CSS 补充收纳状态、按钮及减少动态效果；保留原图片节点和缓存。
4. 扩展真实浏览器观片台验证：入场、收纳/展开、手动打断、自动播放/暂停/末端、减少动效与原片不变；运行前端单测、构建及观片台烟测。

后续“继续”已推进本地 0.10.1 打包；未自动发布 GitHub。62 项前端测试、真实浏览器观片台回归、独立运行时验证通过；便携启动与 0.10.0 → 0.10.1 的真实安装覆盖升级通过，图库与配方保留。实际安装后的收纳空白台面和重新展开也已验证。

## 0.10.2 屏幕比例与统一动效起点

用户反馈大量照片挤在中间：旧算法在照片超过 24 张后几乎固定为 7 列，再按高度缩小整组，导致宽屏留白。改为按实际台面可用区域计算多组对齐行布局，以拟合后的有效照片面积选择排列；每张照片保持自身比例，预留工具栏与底部导览位置。自动平铺在窗口尺寸变化时重新适配，手动缩放或移动后保留手动视图；旧版缩放缓存重新适配。

收纳和平铺统一使用底部导览中央作为所有照片的动效起终点。

用户明确要求“改好之后，直接打包，不测试”。此版仅执行必要的编译与打包，不运行单元测试、浏览器回归、运行时烟测或安装升级测试；0.10.1 的历史通过记录不作为 0.10.2 的测试结论。

正在使用的软件锁住了默认构建目录中的运行时文件，因此打包脚本支持 CARGO_TARGET_DIR；本次使用 product/build/target-0.10.2 的独立目录构建，保留正在使用的软件进程。

## 0.10.3 恢复老款胶片样式

根据用户对比截图，撤回 0.10.2 的等高对齐行：图片高度变小后，固定 60 的上下片孔条占比增大，竖图也过窄。恢复原有 180 等宽胶片、按原图比例决定高度、横向 28 与纵向 48 的留白；按窗口可用宽高选择合适的列数。旧版样式与屏幕自适应同时保留，仍从底部中央收纳和展开。更新布局缓存版本，并约束顶部胶片文字和底部条码避免溢出。

延续用户要求，0.10.3 仅编译打包，不运行测试。

## 0.10.4 自选台面与单张收纳

实施范围集中在现有 FilmTable、Lighttable 与共享 CSS，不新增引擎。

- 将台面展示名单与底部选中照片分开保存，并随位置写入既有本地记录。底部点击只选中，拖入台面才加入展示；重复拖入更新位置。
- 底部使用内部照片 ID 的 HTML 拖放数据，台面只接受当前范围内的照片。加入时保留既有照片的位置和大小，空台面上的首张使用适合查看的尺寸。
- 拖动台面单张时，右侧出现毛玻璃半圆收纳区，命中高亮，松手后沿动效返回底部，展示名单即时更新。
- 一键收纳清空展示名单，一键平铺恢复全部批次；收纳后的图片节点保留缓存。底部添加台面标记与数量，并支持横向滚动。
- 清理单张动效取消与退出；旧版胶片样式、响应式列数、开场和联排播放继续沿用。

按用户持续偏好直接编译打包，不运行单元测试、浏览器测试或安装升级测试。

Windows 桌面窗口关闭 Tauri 默认的原生文件拖放处理器，按随附配置 schema 要求启用 WebView2 内部 HTML5 拖放；文件选择对话框继续保留。
