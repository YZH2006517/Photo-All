# 创作暗房设计语言：安全灯下的一张纸

这份文档写给之后接手创作暗房的人，也写给下一次重做画面的自己。前半部分是规则，后半部分是这一轮踩过的坑和心得。规则以当前源码 `product/ui/WetLab.tsx` 与 `product/ui/darkroom.css` 为准。

## 一句话

创作暗房不是一个「三维化的调色面板」，而是一张站在台前、低头看着的暗房工作台。主角是一张相纸，所有东西都只为它的下一步服务。

## 一、母题：一张纸的旅程

- 四个工位讲的是同一张纸的旅程：
  1. 配方：在台上调好药液。
  2. 显影：药液倒进显影罐，翻转搅动。
  3. 冲印：相纸依次进显影盘、停显盘、定影盘。
  4. 晾干：夹上绳子，干了以后写回照片。
- 每个场景只回答一个问题：「这张纸现在要去哪里？」回答不了这个问题的物件，就不该出现在画面里。
- 场景之间要有连续感：镜头沿着台面横移过去，不做硬切；冲洗记录卡跟着你走，一项项打勾。

## 二、镜头

| 规则 | 做法 |
| --- | --- |
| 站在台前低头看 | 俯角约 45°–50°，视场角 31°，镜头离台面近 |
| 只拍台面 | 不拍墙、架、砖。台面延伸到画面外，远处靠雾和光衰减自然落入黑暗 |
| 物件少而大 | 每个工位只有 3–5 件主要物件，填满画面中部 |
| 转场是走过去 | 切换工位时，镜头从侧面横移入场；如果用户开了「减弱动态效果」，就直接到位 |

**心得**：第一版沿用了平视的镜头，把墙、木架和整张桌子都拍了进去，看上去像产品展示图，没有人站在台前的感觉。改成高位俯视以后，几乎不用再加任何东西，画面就有了「我正在操作」的代入感。镜头决定了一半的氛围。

## 三、光

- **一个光源讲完故事**：头顶一盏柔和的红橙色安全灯，形成一个光池。中心是 `#ff8a5e` 的暖红，边缘落到 `#120302` 的近黑。
- **补光同色**：天光补光用红色系，地面反光用深红。不要引入冷色的轮廓光。
- **不要热点**：没有清漆，泛光只保留到几乎看不出（0.06），高光不能刺眼。暗房里的东西是被光「浸着」的，而不是被光「打亮」的。
- **看片灯**：底栏的「白光」把整个房间切成中性白光，用来判断真实颜色。它只改灯光，不碰配方。红灯下的东西好看但不准，这个开关就是给判断颜色用的。

**心得**：第一版为了显得「高级」，加了强泛光、清漆桌面和玻璃折射。结果安全灯在画面里炸成一团光斑，钢盘边缘也一直闪。去掉这些以后，画面反而第一次像真正的暗房。在红灯环境里，反光越少越可信。

## 四、材质与配色

- **一律哑光、做旧**：
  - 木纹的光泽要低。
  - 钢件是暖锡色的磨砂金属。
  - 搪瓷是灰米色和深棕色。
  - 相纸和卡片是旧米黄色。
  - 玻璃用磨砂。
  - 药液是深色、静止的液面，只泛起很轻的波纹。
- **器具颜色要向光靠拢**：所有器具都落在暖棕、低饱和的色域里。白色、鲜红、亮黄这类颜色，在红灯下会跳出画面。
- **唯一保留真实颜色的是照片本身**：相纸上的影像不受光照影响、不做色调映射，因为用户要看的正是它的颜色。

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| frame | `#050202` | 取景框与页面底色 |
| shadow | `#120302` | 光池边缘、雾 |
| paper | `#f2e2c8` | 界面正文 |
| safelight | `#ff8a5e` | 光池中心 |
| ink | `#e8553c` | 手写字、箭头、印章、当前状态 |
| dim | `#9a7a66` | 次要文字 |
| faint | `#5f463a` | 未选中、禁用 |

**心得**：用户一眼就指出「除了配方架，其他器具太突兀」。原因是我在白光的思路下给器具配了「正确」的颜色：白搪瓷、红漆帽、不锈钢、彩色胶头。可在一盏红灯下，正确的颜色是和光同一个家族的颜色。判断配色时，要在最终的灯光下看，而不是在想象里的日光下看。

## 五、造型

- 比例略圆、厚实，像手工做的道具，不追求工业级的细节。
- 每个物件都必须能操作：拖瓶、拨表、拖量杯、夹相纸、挂绳子。不放纯装饰的杂物。
- 计时表、旋钮这类需要读数的器具，要后仰朝向镜头（约 48°），底下垫楔形底座，不能垂直立着让人斜着看。

**心得**：表盘一开始是竖着放的，俯视镜头下只能看到一个扁椭圆。「朝向观看者」这条规则不只适用于文字，也适用于所有需要读的东西。

## 六、两种声音：打字机与手写

界面上只有两种字，各管一件事。

| 声音 | 字体 | 位置 | 用途 |
| --- | --- | --- | --- |
| 打字机 | Courier New + 仿宋 | 黑色取景框的边沿 | 场景名、步骤、帧号、工具链接 |
| 手写 | Ink Free + 楷体 | 三维场景里、画面底部 | 下一步提示、指向物件的短语和箭头 |

- **打字机说事实**：例如 `SCENE 03 — THE TRAYS`、`FRAME 01 OF 03`。场景名切换时逐字打出，末尾有闪烁的光标。
- **手写说人话**：例如「等一等…」「放这里」「嘘，点我」。红色，略微倾斜。底部的一句会逐字写出；场景里的短语配一支先画出来、再写字的手绘箭头。
- **中文和拉丁文的分工**：
  - 不重要、装饰性的信息用拉丁文，例如场景英文名和帧号。
  - 用户要读懂、要操作的东西一律用中文，例如工具链接、提示和按钮。
- **只用系统字体**：Windows 自带的仿宋、楷体、宋体、Courier New、Ink Free 已经够用，不另外打包字体，打 exe 时不会增加体积。

**心得**：底栏一开始我把工具全写成英文小字，看起来很有「电影感」，但用户要的是能用。「装饰可以用拉丁文，操作必须用中文」这条分界，比「全中文」或「全英文」都更合适。

## 七、界面：整屏是一个取景框

- 整个屏幕是一个黑色圆角取景框，三维画面只在框里。
- **上边框**：返回、场景名、四个步骤、帧号、重置镜头。
- **下边框**：照片切换、胶卷选择、显影控制，以及一排中文工具链接（照片、对比、白光、配方、收藏、撤销、重来）。
- 「应用到照片」是唯一的强调动作，做成一枚略微倾斜的红色印章。
- 按钮的无障碍名称保持不变，例如「开始显影」「对比原有调整」「撤销暗房调配」，自动化测试和读屏软件都靠它们定位。视觉上的文字可以改，无障碍名称不能随便改。

## 八、提示：工作台在跟你说话

提示不是写死在界面上的说明书，而是由场景根据当前状态实时给出：

- **底部一句**：说明现在该做什么，或者正在发生什么，例如「翻过来，再翻回去」「出来了。夹起来，放进停显盘」。
- **场景里一句短语加一支箭头**：指向下一个该碰的物件，并实时跟着那个物件在画面中的位置移动。
- **该等的时候就让人等**：显影盘里的影像慢慢浮现，晾绳上的相纸慢慢摆停，不用加速条或进度百分比去催。

**心得**：之前的提示是每个场景一句固定说明。改成由状态驱动的「一句话 + 一支箭头」以后，四个场景才真正串成了一条流程，用户不需要读说明就知道下一步。

## 九、节奏与动效

- 慢、有分量，一次只动一样东西。
- 动效只用来表达状态变化：倒液、翻罐、波纹、浮现、摆动、打字、写字。不做悬停时到处浮动的装饰动画。
- 尊重「减弱动态效果」：打开后，打字和书写直接出全文，镜头直接到位，工序保留必要的动作。

## 十、过程心得

1. **先看清别人好在哪里，再动手**：第四轮我按「更精致」的方向做加法，结果用户说还是粗糙。真正的差距不在细节多少，而在镜头、光和配色这三件事。先把参考拆成具体规则（俯视、近、无杂物、无反光、柔光），比直接加模型有效得多。
2. **先定语言，再重构**：先写清母题、镜头、光、材质、字体、节奏，让用户确认方向，然后一次性重构。这样比在旧结构上反复修补快，也不会越改越乱。
3. **每改一处就截图对照**：所有判断都以最终画面为准。无头浏览器按固定尺寸截下四个场景，比在面板里手动切换可靠。
4. **流程逻辑和画面分开**：配方映射、预览和保存管线一行没改，所以每次大改画面后，单元测试和冒烟测试都能直接证明功能没被破坏。
5. **保护交互契约**：场景对外暴露的 `data-*` 属性、目标坐标和按钮无障碍名称都保持不变，测试才能跟着画面一起演进，而不是每次都被推倒重写。
6. **注意环境细节**：在 Windows 上用脚本改文件，要保持 CRLF 行尾，否则差异会大得失真。在会强制开启彩色输出的终端里跑冒烟测试，要关掉颜色，否则测试等不到服务器的就绪行。

## 检查清单

改动创作暗房的画面之前，逐条确认：

- [ ] 画面里有没有和当前这一步无关的物件？
- [ ] 镜头是不是站在台前低头看？台面以外的东西是否都落进了黑暗里？
- [ ] 有没有刺眼的高光、清漆反光或泛光光斑？
- [ ] 新器具的颜色在红灯下是否和光同一个家族？在「白光」下是否依然合理？
- [ ] 需要读的东西是否朝向镜头？
- [ ] 新文字属于打字机还是手写？操作类文字是不是中文？
- [ ] 新动作有没有在状态里给出底部提示，必要时给出箭头？
- [ ] 无障碍名称、`data-*` 属性和目标坐标是否保持不变？
- [ ] 单元测试、浏览器冒烟测试和四个场景的截图是否都过了一遍？
